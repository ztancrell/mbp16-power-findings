Why the 2019 16-inch MacBook Pro slows down a few minutes into a game, and how to keep it from happening

  • The SMC, the system controller inside the T2 chip, cuts the power. The charger, the AMD driver, ACPI and the chip temperatures are not the cause.
  • It gives the CPU and GPU one shared power budget: about 82 W when cold, falling as the case warms, to roughly 65–72 W in our capped runs and as low as 54–60 W under full stock load.
  • The budget is fixed in Apple's signed SMC firmware. No setting, SMC key or driver option raises it.
  • The fix is to stay under it: GPU capped at 32 W, CPU capped at 1700 MHz, the game in Borderless. That ran BF6 with no cut at all and a median of 53 FPS.
How the limit works

One budget, four stages of enforcement

The SMC's zone-0 controller compares two values every second. When the draw stays above the budget, it steps in, harder each stage. Windows, ACPI and the AMD driver only pass its decisions on.

  1. 1
    PZ0F is the smoothed CPU + GPU draw in watts. PZ0E is the budget. It starts at ~82 W and falls as the case sensors warm past their targets, mostly Ts2S past 45 °C.
  2. 2
    While PZ0F is above PZ0E, PZ0T climbs. It adds up the overshoot, roughly 0.5–1.3 per second.
  3. 3
    GPU steps. MSLG rises and reaches the GPU as EGPS: the power limit drops 50 → 45 → 40 → 35 → 30 W, each step 10 % of the power table's limit.
  4. 4
    Hidden CPU cut. MSLC (0–24) slows the real CPU clock from 2300 to about 800 MHz. HWiNFO and ThrottleStop still show 23x, so it looks like nothing happened.
  5. 5
    PROCHOT. When MSLC is at 24 and PZ0T reaches ~98, the CPU drops to 8x and the GPU to 300 MHz: ~10 FPS, in pulses of 4–8 s.
Evidence

Draw against budget, four runs

Each panel is one BF6 session, logged once a second from the SMC. The first two go over the budget and get cut. The last two stay under it and never do. Same game, same map, same machine; only the caps differ.

What fooled us

Three things that looked like the problem and weren't

And a network mouse. Synergy, the tool sharing a keyboard and mouse over the network, dropped input now and then. It looked exactly like the CPU stalling. typeperf showed the CPU running normally each time.

The fix

Stay under the warm budget

Nothing raises the budget, so the fix lowers the draw. Each cap was found by moving it until the SMC stopped cutting.

32 WGPU power limit (soft PowerPlay table)
1700 MHzCPU cap (Windows power plan maximum frequency)
flag 1AMD driver left stock, no bypass
BorderlessBF6 display mode, Low preset

Not proven yet

  • The 11:15 run was ~7 minutes of play. A 15-minute confirmation is still owed.
  • Every run used a MorePowerTool table that also lowers the GPU's maximum voltage to 950 mV. The version being built changes only the power limit, at stock voltage, so it may draw a little more.
  • One machine, one game, one room. 30 W is the safer GPU setting for a hot room, judged from its larger margin; no hot-room run was made.
The hunt

Everything else we tried

The SMC firmware was reverse-engineered as part of this research. That is how we know the budget is fixed in the firmware and that no key or setting raises it. That work is kept in a separate private repository and is not published.

  • ACPI. It relays the SMC's bytes to Windows; no method writes them.
  • AMD PowerPlay and VBIOS. The cut is a forced power state applied on top of the table.
  • Writing SMC keys. A new PZ0E is overwritten within a second; no key holds the ceilings. One key pair can freeze the budget; a guarded test is written but has not run yet.
  • EFI settings. Its CPU power limit is the same register ThrottleStop writes.
  • The charger. Already Apple's 96 W, the most this model takes.
  • Chip temperature. PROCHOT fired with the GPU hot spot under 95 °C.
  • Case temperature as the trigger. Same Ts0S, no cut while the draw is under budget. It only sets the budget.
  • Bypassing the GPU steps. With the driver flag at 0 the GPU ignores MSLG, so the SMC goes straight to MSLC and PROCHOT.
  • Turbo off. Unplayable.
  • Patching the SMC firmware. Signed and verified by the T2. Studied, not attempted.
Status

Next

The fix is being built into gamebooster-rs for owners who have never used MorePowerTool or ThrottleStop: one program that installs the 32 W GPU table, caps the CPU only while BF6 runs, and keeps BF6 in Borderless. It changes nothing on any other machine. Linux was not measured; its AMD driver ignores the SMC's GPU steps, so it would likely behave like the bypass runs.

Measured on one 2019 16-inch MacBook Pro, 7–8 November 2026, with smclog (a read-only SMC logger), HWiNFO and Windows typeperf. Raw logs are not published. Key names such as PZ0F are the SMC's own.
